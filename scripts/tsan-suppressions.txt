# ThreadSanitizer suppressions for VideoEye (Linux CI, preset linux-test-tsan).
#
# 用法（由 .github/workflows/build.yml 通过 TSAN_OPTIONS 注入）：
#     TSAN_OPTIONS="suppressions=<仓库根>/scripts/tsan-suppressions.txt"
#
# 这里的每一条都必须是**Qt6 自身**的竞争，不是我们代码里的。判定口径（见 workflow
# 里 sanitizer job 的注释）：报头（SUMMARY 行）落在 libQt6Core 等 Qt 库里，而不是
# 我们自己某个 core/ ui/ 的 .cpp —— Qt 从来就不是 TSan-clean 的。
#
# 我们自己的竞争一律不许往这里塞：CI 上真红过的那几处（MediaPlayer::RequestCancel
# 写 deadline_us、AudioOutput 新线程读正在被赋值的 open_thread_、QThread 在 finished
# 之后没 join 就析构）都是在代码里修掉的，没有一条用 suppression 盖过去。

# QThread 内部的条件变量：工作线程退出路径上动它，主线程这边析构 QThread。
# 即便 finished 已经发出（QtWorkerOwner 那边也补了 wait()），libstdc++/Qt 的部分
# 同步原语 TSan 仍然看不见，报头落在 libQt6Core 的 QWaitCondition 析构里。
race:QWaitCondition::~QWaitCondition

# QArrayData 的分配/再分配：两个 QThreadPool 的内部线程在 Qt 自己的容器上互相
# 撞（Qt 的隐式共享用的是原子引用计数，TSan 不认这套同步）。典型场景是
# AudioVizRenderer 那组单线程用例里 Qt 自己起的线程池 —— 我们的代码一个线程都没起。
race:QArrayData::reallocateUnaligned
race:QArrayData::allocate
